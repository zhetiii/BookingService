# Архитектура системы BookingService

## Описание системы
**BookingService** — это веб-сервис для поиска и бронирования номеров в отелях. Система позволяет клиентам быстро находить свободные номера на нужные даты, а администраторам — управлять номерным фондом. Главная задача архитектуры — обеспечить высокую скорость поиска при больших нагрузках и гарантировать надежное сохранение данных о бронированиях без риска двойного бронирования (Double Booking).

## Основной пользовательский сценарий
1. Пользователь отправляет запрос на поиск свободных номеров на выбранные даты.
2. Запрос проходит через **API Gateway**, который защищает систему от перегрузки (Rate Limiting) и направляет запрос в **API Service**.
3. Сервис сначала проверяет наличие закэшированного списка номеров в **Redis**. Если данные есть (Cache Hit), они мгновенно возвращаются пользователю.
4. Если данных в кэше нет (Cache Miss), сервис обращается к **PostgreSQL**, получает список, сохраняет его в **Redis** и возвращает пользователю.
5. Пользователь выбирает номер и оформляет бронь. Сервис сохраняет транзакцию в **PostgreSQL** и инвалидирует (сбрасывает) соответствующий кэш в **Redis**.
